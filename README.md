# zui-sokol

A [sokol](https://github.com/floooh/sokol) backend for
[zui](https://github.com/AaronJClausen/zui), through
[sokol-zig](https://github.com/floooh/sokol-zig): it collects sokol_app
events into zui's frame records, measures text through zui's text
contract, and draws zui's frames as a renderer (zui's renderer contract)
with sokol_gl and sokol_debugtext, on D3D11 (Windows), Metal (macOS) or
OpenGL (Linux).

## Requirements

- Zig **0.16.0**
- zui, fetched automatically
- sokol-zig, fetched automatically
- On Linux: `libx11-dev libxi-dev libxcursor-dev libgl1-mesa-dev libpulse-dev`

## Run the tour

```sh
zig build demo
zig build demo -- --screen gallery         # start on one screen
zig build demo -- --frames 900 --cycle 40  # visit every screen, 40 zui frames each, then quit
zig build demo -Dgl=true                   # force OpenGL instead of D3D11 or Metal
zig build test-tour                        # declare every screen headlessly and check it fits
```

The demo is a tour of what zui does today, one screen per feature. A
strip along the bottom times every zui frame: zui frames against display
frames, why each frame was declared (input, a resize, `requestFrame`, a
`requestFrameAt` deadline, a source), what `nextFrame` asked for, the cost
of `beginFrame`, declaration and layout, element and command counts, and
how many texts missed the measurement cache. **Ctrl+I** opens a draggable
frame inspector with the last 120 frames, the frame's limits and
diagnostics, and the environment.

| Screen | What it shows |
|---|---|
| Welcome | `requestFrameAt` ticking a clock once a second with no frames between; floating hints; focusable cards |
| Layout Lab | every sizing rule, alignment and gap on a live container; the knobs generated by `zui_reflect`; sizes read back with `rectOf`; the same layout printed as Zig |
| Box Storm | up to 14,000 animated boxes, a 90-deep spiral of `percent` containers, and text walls that either hit the whole-string cache or miss it every frame |
| Infinite Gallery | 10,000 tiles in a virtualized scroll container, loaded through `KeyedLoads` on other threads with progress, failures and cancellation; a hand-made scrollbar |
| Mission Control | `Latest` telemetry, a `Stream` log that a burst overflows into the diagnostics, a `Task` rocket launch with abort; producers run only while `framesSinceRead` says someone is watching |
| Window Manager | draggable floating windows with z order, a taskbar with tooltips, `attach_to = .element` with every anchor pair, a modal dialog in a focus scope |
| Robot Workshop | a robot editor generated by `zui_reflect` from nested structs, and environment changes (theme, contrast, reduced motion, text scale) as if the OS sent them |
| Pixel Pad | painting through `pointerLocal` on one element, tools on keys, undo with chords, and a live view of `keyEvents` and `typedText` |
| Typography | the six fonts, size, letter spacing, line height, wrap and alignment, a column to drag-resize, and a marquee looped with `measureText` and `setScrollOffset` |
| Classic | `examples/showcase.zig`, the same UI as the zui-terminal demo, so the renderers can be compared |

Ctrl+1 to Ctrl+0 jump between screens, Ctrl+= and Ctrl+- zoom (through
`FrameParams.zoom`), Ctrl+L declares a frame at every refresh to watch the
costs live, and Tab moves focus.

## Conformance

`zig build conformance` runs zui's renderer suite
(`zui_testing.expectRendererConforms`) against the renderer, in the first
frame of a sokol_app window: `src/conformance.zig` reads each frame back
with `glReadPixels` before the window presents it, so the suite checks
every clip and fill by its pixels. sokol_gfx cannot read a frame back, so
the suite always renders with OpenGL, whatever `-Dgl` says. CI runs it on
Linux under `xvfb-run`, and it passes on Windows.

## Developing against a local zui

`build.zig.zon` pins zui to a commit. To build against a zui working copy
instead, without editing it:

```sh
zig build test --fork=../zui
```

To move the pin, push the zui change and run
`zig fetch --save=zui git+https://github.com/AaronJClausen/zui#<commit>`.

## How zui maps onto sokol

| zui | sokol |
|---|---|
| `rectangle` | sokol_gl quads, or a triangle fan with each corner's own radius |
| `border` | a ring of triangles inside the bounds, with per-edge widths and per-corner radii |
| `text` | sokol_debugtext, one call per wrapped line; `FontId` 0–5 picks one of its fonts; with letter spacing, each glyph is placed on its own |
| `image` | a textured sokol_gl quad (`zui_sokol.Image`: a view and a sampler) |
| `clip_begin` / `clip_end` | `sg.applyScissorRect` per layer, at the record's `scale × zoom` |
| mouse and touch | `MOUSE_*` and `TOUCHES_*` events, in order; each touch is a pointer of its own |
| wheel | `MOUSE_SCROLL` events, flipped and scaled by `InputCollector.wheel_step` |
| keys | `KEY_DOWN` and `KEY_UP` with their modifiers, repeat flag and key code as the scancode; `CHAR` as text |
| focus | `FOCUSED` and `UNFOCUSED` as the environment's `window_focused` |
| cursor request | `sapp.setMouseCursor`, through `HostRequestApplier` |

sokol_gl and sokol_debugtext each batch their own draws. To keep zui's
paint order, the renderer starts a new layer whenever a shape follows text
or the clip changes, then replays the layers in order, each under its own
scissor rectangle.

Current limits:
- **Bitmap text.** sokol_debugtext's fonts are 8×8 and printable ASCII
  only; other code points draw as `?`. Glyphs are `Text.glyph_scale` of
  the text size, and every glyph has the same advance.
- **No idle sleep.** sokol_app presents at every display refresh, so the
  process never sleeps. The demo declares a zui frame only when
  `nextFrame` or new input calls for one, and otherwise redraws the frame
  it holds; untick "1 Hz" in its header and an idle screen declares none.
- **No IME window.** sokol_app cannot place one, so a text-input request
  is not applied.

## Use it in your application

```zig
const zui_sokol = @import("zui_sokol");
const zui = zui_sokol.zui;
const Ui = zui.Context(zui_sokol.config(.{}));

// in sokol_app's init callback, after sg.setup:
renderer = .init(&text);
renderer.clear_color = background;

// in the event callback:
input.handleEvent(event, sapp.dpiScale(), now());

// in the frame callback:
const params: zui.FrameParams = .{ .now = now(), .viewport = viewport, .scale = sapp.dpiScale() };
ui.beginFrame(&.{ .params = params, .events = input.take() });
// ... declare your UI ...
const frame = ui.endFrame();
host_requests.apply(frame.requests());
try renderer.zuiSubmit(.library, frame); // one swapchain pass, cleared to clear_color
ui.release(frame);
```

`zui_sokol.Renderer` implements zui's renderer contract. Its surface is
`.library`, sokol_app's swapchain, and, built with `-Dgl=true` on Windows,
also `.win32`: a native host's window, such as
[zui-host](https://github.com/AaronJClausen/zui-host)'s, which the
renderer draws into without sokol_app. There it makes the window's OpenGL
4.3 context and sets sokol_gfx up itself, and presents with vsync:

```zig
var renderer: zui_sokol.Renderer = try .initForSurface(&text, host.zuiSurface(.main));
defer renderer.deinit(); // also shuts sokol_gfx down
try renderer.zuiSubmit(host.zuiSurface(.main), frame);
```

zui-host runs the tour this way: `zui_sokol_tour` exports the tour's
application, so another loop can run it unchanged. `zui_sokol.config(...)` builds the
`Config` from its declarations: `Text` is `zui_sokol.Text`, `ImageHandle`
is `zui_sokol.Image`, and there are no optional commands and no
`CustomData`, so the renderer's `switch` over the commands names exactly
the base commands and `image`.
